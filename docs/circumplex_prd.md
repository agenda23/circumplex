# Product Requirements Document (PRD)
## プロダクト名: Circumplex (サーカムプレックス)

### 1. プロダクト概要
**1.1. コンセプト**
「Circumplex」は、Webブラウザ上で動作するWebGLベースの次世代オーディオビジュアライザー兼VJアプリケーションである。
従来の「ビートをトリガーとしたノイズ表示」ではなく、アナログL/R信号の「連続的なストリーム」を直接ジオメトリや色彩にマッピングする。音楽情報処理（MIR）とラッセルの円環モデル（Circumplex Model）を用いて曲調をリアルタイムに自律推定し、1時間以上の長尺運用においても視覚的な「飽き」を生じさせない、有機的かつサイバーな映像空間を生成する。

**1.2. ターゲットユーザー**
*   DJ / トラックメイカー (ライブパフォーマンス時の自律VJツールとして)
*   配信者 (OBSの背景やオーバーレイエフェクトとして)
*   一般ユーザー (URLで共有されるインタラクティブなジェネレーターとして)

**1.3. 動作環境・デプロイ**
*   **ホスティング:** Cloudflare Pages 等を利用した静的サイト (PWA対応)。SPA構成（TypeScript + Three.js。Reactおよび React Three Fiber は不採用 — 描画コアはUber Shader + フルスクリーンクアッド1枚のゲームループが本体であり、React/R3Fの宣言的レンダリングの恩恵が薄い一方、長尺運用でのFPS監視・動的解像度制御と再レンダリング機構が衝突するリスクがあるため）。ビルドは Vite を使用。
*   **対応デバイス:** 
    *   PC (Google Chrome 最新版 推奨)
    *   iOS (iPadOS Safari) - ライブ運用・ジェネレーター用途として
*   **配信連携:** OBS Studio（ブラウザソース、またはウィンドウキャプチャ）

### 2. オーディオ処理仕様 (Audio Architecture)
**2.1. 入力ソースの取得**
*   `navigator.mediaDevices.getUserMedia` を使用してオーディオインターフェースから直接L/Rのアナログ信号を取得する。
*   **【重要】** 取得時はブラウザ側の補正（`echoCancellation`, `noiseSuppression`, `autoGainControl`）を必ず `false` に設定し、`channelCount: 2` を維持して生音（Raw Audio）を取得すること。

**2.2. 帯域分離とルーティング (Web Audio API)**
単一ストリームを `BiquadFilterNode` で以下の3帯域に擬似ステム化し、個別の `AnalyserNode` へルーティングする。
*   **Low (サブベース/キック):** ~150Hz (空間全体のうねり、ベースカラー、カメラシェイク等)
*   **Mid (リード/ボーカル):** 300Hz ~ 3kHz (オブジェクトの形状変容、ノーマルマップの歪み)
*   **High (ハイハット/ノイズ):** 4kHz~ (エッジの発光、パーティクル、グリッチ効果)

**2.3. 特徴量抽出と曲調推定 (MIR & Circumplex Model)**
*   **処理スレッド:** メインスレッドの描画落ちを防ぐため、`AudioWorklet` または `Web Worker` にて計算を行う。
*   **抽出する特徴量:** スペクトル重心、クロマグラム、スペクトルフラックス、RMS、スペクトルフラットネス。
*   **曲調マッピング (ラッセルの円環モデル):**
    抽出した特徴量から、感情価(Valence)と覚醒度(Arousal)の2軸を算出する。
    *   $X$軸 (Valence): 快適度・調性 (-1.0 ~ 1.0)
    *   $Y$軸 (Arousal): 緊張度・激しさ (-1.0 ~ 1.0)
*   **平滑化:** フレームごとの瞬時値ではなく、3〜5秒の移動平均（または指数平滑化）を適用し、曲の展開に合わせた緩やかなメタ遷移を実現する。

### 3. グラフィック・レンダリング仕様 (WebGL / Three.js)
**3.1. データ転送**
*   抽出した3帯域の配列データ（TimeDomain/FrequencyData）を `THREE.DataTexture`（1Dテクスチャ）に変換し、毎フレームGPU(シェーダー)へ転送する。

**3.2. 描画アルゴリズム (Uber Shader)**
*   全エフェクトを内包した1つの「Uber Shader」を構築し、JavaScript側から `uniform` 変数でエフェクトの適用率（0.0〜1.0）をコントロールし、シームレスな状態遷移（モーフィング）を行う。
*   **主たる表現手法:** 
    *   ベクターシンセシス（L/R位相のXY座標マッピング）
    *   Raymarching / SDF（符号付き距離場）によるソリッドな3D構造
*   **低解像度対策:** 細い線（ワイヤーフレーム）を避け、太いSDFや面構成を基本とする。低解像度時にはEffectComposerによるBloom（発光）や意図的なモザイク（ピクセレーション）で粗さをアートスタイルに昇華させる。

**3.3. カラーマッピング (HSL / Oklch)**
音色を濁りのない色に変換するため、RGBの直接操作ではなくHSL/Oklch色空間をシェーダー内で計算する。
*   **Hue (色相):** Mid帯域の支配的周波数（ピッチ）、およびCircumplex座標の極座標角度。
*   **Saturation (彩度):** 倍音の豊かさ（波形の複雑さ）、およびCircumplex座標の半径。
*   **Lightness (輝度):** RMS（音量エンベロープ）。

### 4. 運用・システム制御仕様 (System & Auto-Scaling)
**4.1. 長尺運用向けメタ遷移**
*   **自律的LFO:** シェーダー内に極低周波（例: 0.01Hz）の時間軸を持たせ、同じ入力でも数十分単位で色彩のベース位相やノイズシードが変化し続ける設計とする。

**4.2. 動的処理量調整 (Auto-Scaling)**
熱停止（サーマルスロットリング）やメモリリークを防ぐための自律制御。
*   **FPS監視:** 過去120フレーム程度の移動平均FPSを監視。
*   **動的解像度低下:** FPSが閾値（例: 50fps）を下回った場合、`renderer.setPixelRatio` を動的に下げる（最小0.5程度）。安定すれば復帰させる。
*   **エフェクト間引き:** 解像度低下で解決しない場合、Uber Shader内の重い処理（フラクタル反復数、高品質AA）を自動でオフにする。

**4.3. スリープ回避**
*   `navigator.wakeLock.request('screen')` を使用し、長時間の稼働中に端末がスリープするのを防ぐ。`visibilitychange` イベントでの再取得ロジックも実装する。

### 5. UI / UX 仕様 (Interface)
UIは「映像美を損なわない」ことを大前提とし、以下の2系統を用意する。

**5.1. TUI (Text-based User Interface) ログ / HUD**
*   **実装:** Canvas上の `pointer-events: none` のDOM（等幅フォント）として実装。
*   **HUD:** 画面四隅に `[ FPS: 60 | SCALING: 1.0x | RMS: L 0.8 / R 0.8 ]` 等のステータスを常時表示。
*   **ログ:** `console.log` 等をフックし、システム状態（動的解像度変更の通知、エフェクト遷移のログなど）をターミナル風にオーバーレイ表示。サイバーパンク的なVJ演出を兼ねる。

**5.2. コントロールパネル (設定モーダル)**
*   **呼び出し:** 
    *   PC: 特定のキー入力（例: `` ` `` または `Esc`）。
    *   iOS: マルチタッチジェスチャー（例: 2本指ダブルタップ）。
*   **機能:**
    *   オーディオデバイスの選択・接続開始。
    *   マニュアル・オーバーライド機能（自動解像度調整の無効化、特定カラー/エフェクトの強制固定）。
    *   パフォーマンスプロファイラの詳細表示。
    *   キャッシュクリアおよびPWA（Service Worker）の強制アップデートボタン。

**5.3. 状態のURL共有 (Shareability)**
*   現在のUI設定状態（パラメータ群）をBase64等でエンコードし、URLクエリパラメータ（例: `?p=...`）に同期させる。
*   `?ui=false` などのパラメータで、コントロールパネルの表示可否やクリーンモードを制御できるようにする。

---

### 6. OBS / 配信連携仕様
画面キャプチャの負荷を避けるため、以下のルーティングをサポートする。
*   **ブラウザソース直接入力:** UI非表示モードのURLをOBSのブラウザソースとして読み込む。
*   **PiP (Picture in Picture) キャプチャ連携:** 
    1. PCブラウザで動作時、`canvas.captureStream(60)` で映像ストリームを抽出。
    2. 隠し `<video>` タグに流し込み、ブラウザ標準のPiP APIでフローティング表示。
    3. OBS側でその軽量なPiPウィンドウのみを「ウィンドウキャプチャ」する機能を提供する。
